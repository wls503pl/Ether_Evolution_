# EIP1155

Both **ERC20** and **ERC721** correspond to a single token contract. For example, if we want to make a large-scale game like ***World of Warcraft*** on Ethereum, each piece of equipment needs to deploy a contract.<br>
Deploying and managing thousands of contracts is very cumbersome. Therefore, Ethereum **EIP1155** proposes a multi-token standard called **ERC1155**, which allows a contract to contain multiple homogeneous and heterogeneous tokens.<br>
ERC1155 is widely used in GameFi applications, and well-known blockchain games such as Decentraland and Sandbox use it.<br>

In simple terms, ERC1155 is similar to the previously launched non-fungible token standard ERC721: in ERC721, each token has a tokenId as a unique identifier, and each tokentokenId corresponds to only one token;<br>
in ERC1155, each type of token has an id as a unique identifier, and each tokenid corresponds to a type of token. In this way, the types of tokens can be managed heterogeneously in the same contract, and each type of token has a URLuri to store its metadata,<br>
similar to the tokenURI in ERC721. The following is the metadata interface IERC1155MetadataURI contract ERC1155:<br>
```
/**
 * @dev Optional ERC1155 interface that adds the uri() function for querying metadata
 */
interface IERC1155MetadataURI is IERC1155 {
    /**
     * @dev Returns the URI of the token type `id`.
     */
    function uri(uint256 id) external view returns (string memory);
```
How to distinguish whether a certain type of token in ERC1155 is a homogeneous token or a non-homogeneous token? In fact, it is very simple: if the total amount id corresponding to a certain type of token is 1, then it is a non-homogeneous token,<br>
similar to ERC721; if the total amount id corresponding to a certain type of token is greater than 1, then it is a homogeneous token, because these tokens share ids, similar to ERC20.

## IERC1155 interface contract

The IERC1155 interface contract abstracts the functions that EIP1155 needs to implement, which includes 4 events and 6 functions. Unlike ERC721, because ERC1155 includes multiple types of tokens, it implements batch transfers and batch balance queries, and operates multiple tokens at one time.

```
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.21;

import "https://github.com/wls503pl/Ether_Evolution_/blob/ee/ERC721/IERC165.sol";

/**
* @dev Single-type token transfer event
* Released when the tokens of type `value` and `id` are transferred from `from` to `to` by `operator`.
**/
event TransferSingle(address indexed operator, address indexed from, address indexed to, uint256 id, uint256 value);

/**
 * @dev Batch token transfer event
 * ids and values ​​are arrays of token types and quantities to be transferred
 */
event TransferBatch(
    address indexed operator,
    address indexed from,
    address indexed to,
    uint256[] ids,
    uint256[] values);

/**
 * @dev Batch authorization event
 * Released when `account` authorizes all tokens to `operator`
 */
event ApprovalForAll(address indexed account, address indexed operator, bool approved);

/**
 * @dev Released when the URI of the token of type `id` changes, `value` is the new URI
 */
event URI(string value, uint256 indexed id);

/**
 * @dev Position query, returns the holding amount of tokens of type `id` owned by `account`
 */
function balanceOf(address account, uint256 id) external view returns (uint256);

/**
 * @dev Batch position query, the lengths of `accounts` and `ids` arrays must be equal.
 */
function balanceOfBatch(address[] calldata accounts, uint256[] calldata ids)
    external
    view
    returns (uint256[] memory);

/**
 * @dev batch authorization, authorize the caller's token to the `operator` address.
 * Release {ApprovalForAll} event.
 */
function setApprovalForAll(address operator, bool approved) external;

/**
 * @dev Batch authorization query, if the authorized address `operator` is authorized by `account`, return `true`
 * See {setApprovalForAll} function.
 */
function isApprovedForAll(address account, address operator) external view returns (bool);

/**
 * @dev Secure transfer, transfer the token of `amount` unit `id` type from `from` to `to`.
 * Release {TransferSingle} event.
 * Requirements:
 * - If the caller is not the `from` address but an authorized address, it is necessary to obtain authorization from `from`
 * - The `from` address must have sufficient positions
 * - If the receiver is a contract, it is necessary to implement the `onERC1155Received` method of `IERC1155Receiver` and return the corresponding value
 */
function safeTransferFrom(
    address from,
    address to,
    uint256 id,
    uint256 amount,
    bytes calldata data) external;

/**
 * @dev Batch secure transfer
 * Release {TransferBatch} event
 * Requirements:
 * - `ids` and `amounts` are of equal length
 * - If the receiver is a contract, the `onERC1155BatchReceived` method of `IERC1155Receiver` needs to be implemented and the corresponding value returned
 */
function safeBatchTransferFrom(
    address from,
    address to,
    uint256[] calldata ids,
    uint256[] calldata amounts,
    bytes calldata data) external;

```

### IERC1155 Event

- **TransferSingle event**: a single-type token transfer event, released when a single currency is transferred.<br>
- **TransferBatch event**: batch token transfer event, released during multi-currency transfers.<br>
- **ApprovalForAll event**: batch authorization event, released during batch authorization.<br>
- **URI event**: metadata address change event, released when the URI changes.

### IERC1155 Function

- **balanceOf()**: Single currency balance query, returns the holding amount of tokens of the ID type owned by the account.<br>
- **balanceOfBatch()**: For multi-currency balance query, the length of the queried address accounts array and the token type ids array must be equal.<br>
- **setApprovalForAll()**: Batch authorization, authorizing the caller's tokens to the operator address<br>
- **isApprovedForAll()**: Query batch authorization information. If the authorization address operator is authorized by the account, it returns true.<br>
- **safeTransferFrom()**: Secure single-coin transfer, transfer the token of amount unit id type from the from address to the to address. If the to address is a contract, it will verify whether the onERC1155Received() receiving function is implemented<br>
- **safeBatchTransferFrom()**: Safe multi-currency transfer is similar to single-currency transfer, except that the transfer amount and token type ids are changed to arrays with equal lengths. If the to address is a contract, it will verify whether the onERC1155BatchReceived() receiving function is implemented.<br>

## IERC1155 Receive Contract

Similar to the ERC721 standard, in order to prevent tokens from being transferred to black hole contracts,<br>
ERC1155 requires the token receiving contract to inherit IERC1155Receiver and implement two receiving functions:<br>
- **onERC1155Received()**: Single currency transfer receiving function, accept ERC1155 safe transfer ***safeTransferFrom*** needs to implement and return its own selector *0xf23a6e61*.<br>
- **onERC1155BatchReceived()**: Multi-currency transfer receiving function, accepts ERC1155 safe multi-currency transfer ***safeBatchTransferFrom*** needs to implement and return its own selector *0xbc197c81*.<br>
```
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.21;

import "https://github.com/wls503pl/Ether_Evolution_/blob/ee/ERC721/IERC165.sol";

/**
 * @dev ERC1155 receiving contract, to accept ERC1155 secure transfer, you need to implement this contract
 */
interface IERC1155Receiver is IERC165 {
    /**
     * @dev Accept ERC1155 safe transfer "safeTransferFrom" needs to return 0xf23a6e61 or "bytes4(keccak256("onERC1155Received(address,address,uint256,uint256,bytes)"))"
     */
    function onERC1155Received(
        address operator,
        address from,
        uint256 id,
        uint256 value,
        bytes calldata data) external returns (bytes4);

    /**
     * @dev accept ERC1155 batch safe transfer "safeBatchTransferFrom"
     * Need to return 0xbc197c81 or `bytes4(keccak256("onERC1155BatchReceived(address,address,uint256[],uint256[],bytes)"))`
     */
    function onERC1155BatchReceived(
        address operator,
        address from,
        uint256[] calldata ids,
        uint256[] calldata values,
        bytes calldata data) external returns(bytes4);
```

## ERC1155 Master Contract

The ERC1155 main contract implements the functions specified in the IERC1155 interface contract, as well as the minting and destruction functions of single/multi-coins.

### ERC1155 Variable

The ERC1155 main contract contains 4 state variables:<br>
- **name**: Token name.<br>
- **symbol**: Token symbol.<br>
- **_balances**: Token holdings mapping, recording the balances of an address account under the token type id.<br>
- **_operatorApprovals**: Batch authorization mapping, recording the authorization of holding an address to another address.<br>

### ERC1155 Function

The ERC1155 main contract contains 16 functions:<br>
- **Constructor**: Initialize state variables `name` and `symbol`.<br>
- **supportsInterface()**: Implement the ERC165 standard and declare the interfaces it supports for other contracts to check.<br>
- **balanceOf()**: Implements balanceOf() of IERC1155 to query the holding amount. Different from the ERC721 standard, you need to enter the holding address account and currency id to be queried.<br>
- **balanceOfBatch()**: Implement balanceOfBatch() of IERC1155 to query the holding amount in batches.<br>
- **setApprovalForAll()**: Implement setApprovalForAll() of IERC1155, batch authorization, and release ApprovalForAll event.<br>
- **isApprovedForAll()**: Implement isApprovedForAll() of IERC1155 to query batch authorization information.<br>
- **safeTransferFrom()**: Implement safeTransferFrom() of IERC1155, single currency safe transfer, and release TransferSingle event. Different from ERC721, here you need to fill in not only the sender from, the receiver to, the token type id, but also the transfer amount amount.<br>
- **safeBatchTransferFrom()**: Implement safeBatchTransferFrom() of IERC1155, multi-currency secure transfer, and release TransferBatch event.<br>
- **_mint()**: Single currency minting function.<br>
- **_mintBatch()**: Multi-currency minting function.<br>
- **_burn()**: Single currency destruction function.<br>
- **_burnBatch()**: Multi-currency destruction function.<br>
- **_doSafeTransferAcceptanceCheck()**: The security check for single-currency transfers is called by safeTransferFrom() to ensure that the ***onERC1155Received()*** function is implemented when the recipient is a contract.<br>
- **_doSafeBatchTransferAcceptanceCheck()**: Security check for multi-currency transfers, called by safeBatchTransferFrom to ensure that the recipient is a contract, and implement the ***onERC1155BatchReceived()*** function.<br>
- **uri()**: Returns the URL where the metadata of the idth token of ERC1155 is stored, similar to the tokenURI of ERC721.<br>
- **baseURI()**: Returns baseURI, uri is the concatenation of baseURI and id.<br>
