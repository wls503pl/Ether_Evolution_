## Introduction

Many applications on Ethereum require random numbers, such as random extraction of tokenIds for NFTs, drawing blind boxes, and random determination of winners and losers in gamefi battles.<br>
However, since all data on Ethereum is public, transparent and deterministic, it cannot provide developers with a method to generate random numbers like other programming languages.<br>
There are currently two methods for random number generation: on-chain (hash function) and off-chain (chainlink oracle).<br>

### On-chain random number generation

Use some global variables on the chain as seeds and use the ***keccak256()*** hash function to obtain pseudo-random numbers. This is because the hash function has sensitivity and uniformity, and can produce "seemingly" random results.<br>
The ***getRandomOnchain()*** function below uses the global variables block.timestamp, msg.sender and blockhash (block.number-1) as a seed to get a random number:<br>
<hr>
function getRandomOnChain() public view returns(uint256) {<br>
    // Remix will report an error when running blockhash<br>
    bytes32 randomBytes = keccak256(abi.encodePacked(block.timestamp, msg.sender, blockhash(block.number - 1)));<br>
    return uint256(randomBytes);<br>
}<br>
<hr>

- Notice：
This method is not safe.<br>
First, the variables **block.timestamp**, **msg.sender**, and **blockhash (block.number-1)** are all public. Users can predict the random numbers generated by these seeds and pick the random numbers they want to execute the contract.<br>
Second, a miner can manipulate **blockhash** and **block.timestamp** so that the generated random number is in his interest.<br>

However, since this method is the most convenient on-chain random number generation method, a large number of projects rely on it to generate insecure random numbers, including well-known projects such as **meebits** and **loots**.<br>
Of course, these projects have all been attacked: attackers can mint any rare NFT they want, rather than randomly selecting it.<br>
